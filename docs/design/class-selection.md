# class付き選出条件・統合仕様

2026-11-03。利用者が今回提示した仕様を、この文書に整理したうえで実装する。既存の旧CSVと選出評価v3は別形式として保存し、自動変換しない。

## 既存実装

- `pickrule.js` は既存条件文法と名前解決、旧CSVの順序依存の3枠充填を担当する。
- `selection-assessment.js` はv3の役割・危険の静的得点と手動ケース参照を担当する。classの辞書順比較とは異なる。
- 新方式は明示的に保存・有効化した場合だけ使う。旧方式の条件パーサー、CSV、データは維持する。

## 入力形式

JSONの包みは `schemaVersion:1, version, updatedAt, rowsCsv, settings`。
CSVの列は次のとおり。

`class,条件,役割ID,操作,候補,充足,強度,重要度,対応条件,前提役割ID,検証,役割種別,メモ`

- class: 1以上の整数。小さいclassを優先。同じclassの行順は使わない。
- 条件: 既存文法で相手6体に適用する。条件成立は役割を担当できる証明ではない。
- 役割ID: 同じclassで同じ仕事をまとめる。同じ仕事の行は操作・充足・強度・重要度・役割種別を一致させる。異なる役割を同じIDへ潰さない。
- 操作: 採用、除外、先発。採用は先発を指定しない。
- 候補: `ゴリランダー;ドドゲザン` のようにセミコロンで区切る。条件内の `|` や `/` と混同しない。名前は既存の自軍名解決を使い一意に解決する。
- 充足: `any` はどちらか1匹、`all` は全候補が必要。除外anyは候補のいずれかを含む選出を避ける、除外allは候補の同時選出を避ける。先発はanyだけ（先発は1匹）。
- 強度: 必須、推奨。必須はclassにかかわらず破れない制約。矛盾は理由付きで候補ゼロとし、勝手に格下げしない。
- 重要度: 利用者が入力する0以上の有限値。適性や勝率ではない。自動的な仮の適性点は作らない。
- 対応条件: 相手6体について、その行の候補が役割を担当できる追加条件。空欄は追加条件なし。条件が成立しても対応条件が不成立なら担当不可。
- 前提役割ID: より上のclassの採用役割が満たされている場合だけ、その行の候補を担当として認める。循環・同class以降への参照はエラー。条件付きリザの役割などに用いる。
- 検証: 確認済み、未評価。未評価は担当可能として加点しない。「採用方針」の確認済みは利用者の方針の確認であり、対戦結果の保証ではない。
- 役割種別: 採用方針、対面処理、後出し、ストッパー、崩し、起点作り、その他。対面処理と後出しは別IDで登録する。同種別だから同一視しない。
- メモ: 根拠や不足の説明。計算条件として解釈しない。

同じ役割IDに複数行を設け、異なる対応条件・前提・候補を登録できる。anyでは確認済みの担当1匹で役割を満たし、重複加点しない。allでは成立した行の候補全員が確認済み・担当可能・選出済みである必要がある。

## 列挙と比較

1. 自軍6体から同種族重複のない3体を全列挙する。設定 `maxSelectedMegaHolders`（0〜3、標準1）を守る。メガの予定形態は種族と実際の石から求める。
2. 各3体に先発3通りを保持する。必須の採用・除外・同時禁止・先発に違反する候補を除外する。
3. 成立した役割をclass昇順に一括評価する。各classの未充足重要度合計、未充足件数の順で比較する。この指標をclassごとに辞書順比較し、下位classで上位classの不足を逆転させない。
4. 同じ役割の得点を担当数で増やさない。未評価も未充足として表示し、対応済みや安全としない。
5. 完全同点だけは選出の自軍登録順、先発の登録順で表示順を固定する。行順は使わない。全候補は残し、軸分岐別にも比較できる。
6. 3体ごとにまとめ、先発違いを別途提示する。先発を選ぶまで適用ボタンは有効にしない。対応範囲から先発を自動決定しない。

同じ1匹しか確認済み担当がいない役割が複数あれば集中を警告する。allで各候補が不可欠な場合も集中の対象とする。複数担当だけで禁止しない。他に候補がいる場合は代替も表示する。全条件を満たせる3体がない場合、必須衝突と推奨不足を区別して示す。

## 現構築向けの軸分岐（明示的な設定）

`settings.axisBranches` は未設定なら無効。有効にする場合は次のオブジェクトを入力する。

`{"charizardRuleId":"char_axis","charizard":"リザードン","garchomp":"ガブリアス","class":2}`

参照役割はclass1・必須の採用方針・候補リザードン1匹・確認済みとする。条件は既存CSVの厳しいリザ採用条件を利用者がそのまま転記する。既存条件は編集画面で参照でき、利用者が転記ボタンを押した場合だけ、その条件文を変更せず編集欄へコピーする。旧CSVの他行や他の除外指定を自動変換せず、保存前に確認できる。空欄・常時成立条件へ自動で緩和しない。

- 参照条件成立: リザ採用を必須とし、ガブとの同時選出を除外する。
- 不成立: リザを除き、ガブ軸とメガ石持ち0体の分岐を残す。各分岐の完成した3体でclass3まで比較する。class2の二分岐はともに軸選択を満たす選択肢であり、ガブを上位classの絶対必須条件にしない。
- 「メガなし」は分岐名でありポケモン名ではない。両者に石があることを検証する。

## 保存・表示

構築では新しい `classPickRules` に保存する。新方式の保存で利用モードをclassへ明示的に変更する。旧CSVとv3評価データは削除・書換しない。従来方式へ戻す操作も用意する。

CSVは行データ、JSONは設定・版を含む全体の持ち運び用とする。対戦作成時にルールの版・内容・モードをスナップショット保存する。旧対戦を後からclass方式へ切り替えない。適用時に候補3体、固定先発、軸分岐、各classの成立条件・担当・不足・根拠を保存する。対戦開始後は適用できない。

表示するもの: 選出案、先発候補、classと条件、候補と実際の担当、対面/後出し等の区分、不足、未評価、役割集中、他案との対応範囲の差、軸別比較。相手先発は未知。初動は未評価。静的結果をシミュレーション・実戦勝率と呼ばない。

## 検証

同classの行順不変、イエッサン＋アシレーヌをゴリランダーで兼任、ゴースト対応のドドゲザン案保持、条件付きリザによる代替、リザ/ガブ排他、ガブ軸/メガなしの完成形比較、先発の独立、推奨不足、必須衝突、未評価の非加点、旧CSVの既存テスト維持、CSV/JSON原子性、対戦スナップショットと理由保存を確認する。
